# DPS150能力与速度证据核验

核验日期：2026-11-04。本轮只检查官网、既有脚本和原始日志，没有操作电源。

## 结论

官方软件的扫描延时、USB命令吞吐、设定寄存器更新、物理输出响应是不同指标。
当前已测到约200次/秒的短时电流设定写入及设定值读回，尚未测得实际输出调制带宽。
不应把200次/秒称为设备官方扫描速度、模拟输出采样率或实际电流跟随速度。

## 官方资料

官网产品页给出DPS150额定0-30 V、0-5 A、最高150 W、CC/CV及可编程功能，
未在已检查的产品文字规格中查到最大远程更新率、输出阶跃建立时间或正弦调制带宽。
未查到不等于厂商绝对没有相关内部指标；当前不能引用为已公布保证值。

官方软件下载页的DPS-150 / IPS3608说明明确给出：

- Current Sweep：步进电流范围0.001-5.000 A，延时1-86400秒。
- Voltage Sweep：步进电压范围0.01-30.00 V，延时1-86400秒。

这些是官方软件扫值功能的参数范围。这里的扫描是按步进和延时改变直流设定，
不是已声明的正弦频率扫描或交流波形发生器能力。每步最短1秒不能直接用于构造
1-2 Hz的多点阶梯正弦；但也不能据此认定硬件无法接收更快的单次设定命令。
顺序输出功能应与上述扫值功能区分；该网页没有在顺序输出段明确给出所有延时边界。

## 本机实际控制了什么

已查询设备：DPS-150，硬件V1.0，固件V1.2。
当前USB协议按115200串口配置连接，原测试脚本采用一发一查且只保留一个待处理查询。

速度测试使用低阻钢管直接跨接输出，电压上限1 V，电流设定在2-10 mA之间变化。
每个步骤依次执行：

1. SET电流设定（字段194）。
2. GET电流设定（同字段194）。
3. 检查返回的浮点设定值是否匹配，并记录主机发送与接收时间。

返回的字段194是设定值，不是独立采样的实际输出电流。
测试序列循环使用九个名义电流水平，并不是正弦波。
实际电压设定字段193只用于固定合规电压，并未在该吞吐测试中连续扫描。

## 原始日志复核

200次/秒档做过8秒和15秒短测，分别1600和3000点设定值全部读回匹配。
15秒复测数据：

|---|---:|

| 实际发送间隔中位数 | 4.9998 ms |
| 实际发送间隔P95 | 5.0894 ms |
| 实际发送间隔P99 | 11.4577 ms |
| 最大发送间隔 | 17.8289 ms |
| 最小发送间隔 | 2.2647 ms |
| 超过10 ms的发送间隔 | 32次 / 2999个间隔 |
| 主机发送迟到P95 | 0.3406 ms |
| 主机发送最大迟到 | 12.8416 ms |
| SET至GET回复往返中位数 | 2.2505 ms |
| 输出遥测195帧数 | 31帧 |
| 输出遥测帧间隔中位数 | 492.53 ms |

200次/秒通过的是任务自定筛选规则：所有设定读回匹配、平均完成率不少于95%、
主机迟到P95不超过标称步长25%。这不是每一步都在5 ms内完成的保证。
迟到后脚本按原目标时间继续追赶，会出现长间隔与短间隔，不能视为严格均匀零阶保持。

240及320次/秒也有完整且匹配的设定值读回，但不满足上述时序规则。
不能把它们称为设备完全无法接受的速率，也不能把200认定为硬件绝对极限。

约2帧/秒的内部输出遥测，不能验证200次/秒的模拟输出变化，也不足以重建2 Hz波形。
内部遥测本身也不是独立电流标定。未测得内部控制环路、DAC实际更新或电极负载响应。

## 对先前理论计算的约束

每秒200次、2 Hz每周期100点、理想阶梯基频损失0.01645%、理想THD约1.814%，
均只适用于均匀更新且实际输出正确保持等假设。已有实机数据不能证明这些假设成立。
进一步的数字低通比较同样不能把条件计算变成实际电源输出或TC接收的等效精度。

既有结论应表述为：自编程序实现并短测了标称200次/秒的电流设定更新与读回；
具备构造低频调制设定序列的控制基础，但带载实际电流波形、幅相和失真尚未标定。

## CC/CV与当前供电边界

ISET在CV状态下是电流上限，不代表负载实际流过该电流。
只有可用电压足够并进入CC范围，才有条件通过ISET构造实际电流调制。
VSET调制则必须考虑负载电化学阻抗，不能直接等同电流调制。
当前输入遥测约9 V，而该电源为降压型，不能据30 V额定上限宣称现供电可输出30 V。
本日纯净水电极通路在1 V/5 mA限流测试中保持CV、内部电流回读0；
它既未证明完全断路，也未建立预期的5 mA恒流，更没有带载正弦保真度证据。

## 2026-11-05 周期性停顿分层排查补充

本轮在输出关闭条件下，将主机迟到、write调用、OS写完成观测等待、GET回包等待分别计时。
200次/秒、30秒复测中，58次写完成观测等待超过5 ms，最长39.529 ms；
长等待起点间隔中位数约0.525秒，自动遥测195帧间隔中位数约0.527秒。
write调用最长0.413 ms，不能将近40 ms停顿简单解释为同样时长的Python计算或阻塞write调用。
主机也有少量独立调度离群值，不能声称Windows调度完全没有影响。

只查询、改电流、去掉逐点查询、补发115200初始化、关闭RTS/CTS、独立接收线程均未消除同类周期性长等待。
关闭通信会话后设定未被接受，也不能作为关闭遥测的替代控制方案。
电源固件周期任务是优先怀疑方向，但尚未通过跨电脑对照/底层USB追踪独立于USB栈证实。

20次/秒通过主机发送节拍测试，并不代表设备逐点即时执行：追加20次/秒逐点SET+GET测试，
200点全部完成，但最长事务仍约46.493 ms。不能把降低更新率称为已消除内部暂停。
