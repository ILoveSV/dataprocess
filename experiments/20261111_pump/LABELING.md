# TC2 水泵实验标注规范

## 整份记录：文件名和元数据

建议今后用 `YYYYMMDD_PUMP_TC2_D03M_B_R06` 作为采集名称。其中 `D03M` 是确认的 3 m，`DUNK` 是未确认距离；`A/B` 是启停模式；`R06` 是当天该批按采集时间递增的序号，不按距离重置。固定记录 ID 是 `YYYYMMDD_PUMP_TC2_R06`，不含待修正的距离和模式。已有 TDMS 和索引保持原名，通过 [record_labels.json](record_labels.json) 映射。

元数据保留 `distance_nominal_m`（原文件夹标称值）与 `distance_m`（确认值）；确认值未知时用 `null`。批内模式按操作描述记录，不从信号峰或模型输出补填。距离未知的记录仍可用于启停回放和状态模型，不用于已确认距离的对比。这里的距离是探测器到水泵的距离。

## 时间段：目标标签

| 标签 | 定义 |
|---|---|
| `STOP` | 变频器通电，泵处于停机状态 |
| `RUN50` | 50 Hz 稳定运行 |
| `RUN30` | 30 Hz 稳定运行 |
| `TRANSITION` | 从命令发出到设备进入下一稳定状态，保留用于测过渡响应，不作为稳定态 |
| `UNKNOWN` | 缺少足够的独立信息确认状态，不作为真值样本 |

- **模式 A：** `STOP → RUN50 → RUN30 → STOP`。**模式 B：** `STOP → RUN50 → STOP → RUN50`。转移动作的计划时刻是采集后 20、50、80 秒，计划稳定时刻是 30、60、90 秒。JSON 中的区间为左闭右开、单位为相对采集开始的秒数，超过 120 秒的尾部没有计划标签。
- 本批区间来源为 `operator_plan`，是名义计划，未经独立逐秒核实。后续保留独立状态记录，按 `record_id, t_start_s, t_end_s, state, label_source` 保存区间。另存实际命令时刻和实际进入稳定状态的时刻，记录参考时钟。用变频器状态日志或同步屏幕录像复核后，另建实测标签，不覆盖原计划；不用识别模型或待测波形给自身生成验证真值。
- **实时任务第一版只评估 `STOP/RUN`**，其中 `RUN30/RUN50` 都映射到 `RUN`，原标签保留。输出可有 `UNKNOWN`，评估时报告覆盖率、停机误报、运行漏报和切换延迟。按整份记录拆分训练与测试，不将模式、距离、计划时间或文件名作为输入。可先回放只使用当前及过去窗口的算法；若保留启动校准，需在测试前独立确认初始停机，并用同一规则做实时与离线评价。
